# Mission: React Query (via TkDodo's "Practical React Query" series)

## Why
Pure interest — no active project or interview deadline. The goal is to go from "used React Query but not comfortable with it" to genuinely understanding how it works and why it's designed the way it is, by working through TkDodo's 33-post series in order.

## Success looks like
- Can explain and correctly apply the core mechanics covered across the series: query keys, caching/staleness, mutations, invalidation, error/status handling, and the more advanced topics (infinite queries, optimistic updates, TypeScript integration).
- Has completed a lesson for each of the 33 posts, building a personal glossary/reference set along the way.
- Can look at an unfamiliar React Query codebase and reason about *why* it's structured a certain way (query key design, abstraction choices), not just what each hook does.
- Can articulate when React Query is *not* the right tool (per post #21, "You Might Not Need React Query").

## Constraints
- Self-paced, multi-session — no fixed deadline.
- Starting point: has used `useQuery`/`useMutation` before but is not fluent — comfortable with basics, shaky on query key design, caching internals, and advanced patterns.
- Follow the 33 posts roughly in their published order (listed in RESOURCES.md), since the series itself is sequenced from foundational to advanced.

## Out of scope
- No specific framework integration beyond what the series itself covers (React Router, TanStack Router are in-scope only because posts #17 and #33 cover them).
- Not chasing a work deadline or interview — depth over speed.
